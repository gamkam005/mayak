# История версий

## Не выпущено

Подписки.

- Подписки в формате готовых конфигов Xray (JSON-массив или один конфиг с
  `outbounds`). Многие панели отдают его клиентам v2rayN/v2rayNG/Happ.
  Outbound берётся целиком, с REALITY, xhttp `extra`, `finalmask` и т. п.;
  дубликаты убираются, цепочки (`dialerProxy`/`proxySettings`) пропускаются.
- Если подписка не скачивается с приёмами против DPI (некоторые серверы
  отвечают на разрезанный ClientHello сертификатом «без имён»), МАЯК
  пробует обычное соединение и только потом живой сервер из пула.
- Ключ подписки в пути (`/subs/<uuid>`, `/sub/<токен>`) скрывается в журнале
  и панели, как раньше скрывались `?key=`/`?token=`.

## 0.3.3 — 2026-11-18

МАЯК на MikroTik: контейнер RouterOS 7.

- Образы `mayak-container-{lite,full}-{amd64,arm64,armv7}.tar` в формате
  `docker save` на пустой основе (scratch): статический mayak и корневые
  сертификаты. Подходят для `/container add file=…` в RouterOS, `docker load`
  и `podman load`. Сборка воспроизводимая, без docker:
  `mikrotik/build-images.sh` (`mikrotik/mkimage.py`).
- `mayak client -redirect адрес:порт` принимает соединения, которые роутер
  перенаправил через dst-nat. Цель берётся из SNI (TLS, порт 443) или Host
  (HTTP, порт 80), поэтому внутри контейнера не нужны iptables, TUN и привилегии.
- Любой флаг клиента можно задать переменной окружения `MAYAK_<ФЛАГ>`
  (`MAYAK_LINK`, `MAYAK_SUBS`, `MAYAK_SUB_STATE`, …). Командная строка важнее.
- `mikrotik/`: пошаговая инструкция для RB4011 и скрипты RouterOS — установка,
  туннель для выбранных сайтов (список адресов заполняет DNS роутера, с
  поддоменами), весь веб-трафик, полный откат. Всё проверено на RouterOS
  7.25.1 CHR: прокси, выборочный и полный режимы, переход на запасные подписки
  при блокировке сервера, откат.
- Android 0.3.3 (`versionCode` 6), пакеты OpenWrt и Windows — те же функции,
  что и в 0.3.2, плюс `-redirect` и `MAYAK_*`.

## 0.3.2 — 2026-11-18

Автообновление из GitHub на всех платформах.

- Источник — последний релиз с пометкой Latest (`releases/latest`);
  pre-release, draft и теги с alpha/beta/rc/pre/dev пропускаются, ставится
  только версия новее установленной.
- `SHA256SUMS` каждого релиза подписан ed25519 (`SHA256SUMS.sig`, открытый
  ключ встроен в программу); скачанный файл сверяется по SHA-256. Без верной
  подписи ничего не ставится. Если GitHub напрямую недоступен — через свой прокси.
- Windows/Linux-клиент: проверка через 30 с после запуска и раз в 6 ч,
  замена exe (старый — `.old`), перезапуск с теми же параметрами (на Linux —
  тот же PID). Выключение: `-noupdate` или файл `noupdate` рядом с программой.
  Флаги `-update-url`, `-update-every`, `-update-delay`.
- Команды `mayak update [-check] [-json] [-asset шаблон] [-out файл] [-proxy]`
  и `mayak sign` (подпись/проверка SHA256SUMS).
- Android 0.3.2 (`versionCode` 5): карточка «Обновления», проверка при
  открытии (не чаще раза в 6 ч) и кнопка «Проверить обновления»; APK
  скачивается и проверяется ядром, ставится системным установщиком
  (подтверждение пользователя). Разрешение `REQUEST_INSTALL_PACKAGES`.
- OpenWrt: `/usr/bin/mayak-update` (opkg на 24.x, замена бинарника на 25.x
  и без пакета), ежедневный cron, UCI `auto_update` (по умолчанию 1),
  `update_url`. Служба запускает клиент с `-noupdate`.
- README: раздел «Благодарности» авторам бесплатных подписок.
- Версии 0.3.0/0.3.1 обновлятора не содержат: 0.3.2 нужно поставить вручную один раз.

## 0.3.1 — 2026-11-17

Windows и OpenWrt догнали 0.3.0. Android не менялся (APK 0.3.0).

- Тег сборки `lite` (`go build -tags lite`): без ядра Xray, ~8–10 МБ вместо
  ~32 МБ. Подписки в такой сборке выключаются с понятным сообщением,
  `/api/subs` отдаёт `available: false`, `mayak picker` отказывается работать.
- Двойной щелчок по `mayak.exe` (и новый флаг `-easy`): маршрут `auto`,
  подписки `reserve`, `subs.json` рядом с программой, на Windows —
  системный прокси. Явно заданные флаги и режим из `subs.json` важнее.
- Флаг `-sysproxy` (Windows): включает системный прокси на адрес `-listen`
  и при выходе возвращает прежние настройки; оставшийся после аварийного
  выхода прокси на тот же адрес выключается.
- На Windows `-desync` по умолчанию — только работающие там приёмы:
  `tlsrec+split,tlsrec:at=sniext+split,multirec+split,split:at=mid`.
- Русский текст в консоли Windows (UTF-8).
- Архив `MAYAK-windows-0.3.1.zip`: `autostart-on.bat` / `autostart-off.bat`
  (ярлык в «Автозагрузке», свёрнутое окно), `stop.bat`, `subs.json`, `ПРОЧТИ.txt`.
- OpenWrt: UCI-опции `route`, `desync`, `doh`, `subs`, `sub_state`, `debug`;
  ссылка не обязательна при `route=direct` или `subs≠off`. Пакеты `mayak`
  (lite) для x86_64, aarch64_generic, aarch64_cortex-a53,
  arm_cortex-a7_neon-vfpv4, mipsel_24kc, mips_24kc и `mayak-full` (с Xray)
  для x86_64 и aarch64. `install-openwrt.sh` проверяет место по размеру
  бинарника.

## 0.3.0 — 2026-11-17

Запасной вход из бесплатных подписок, если свой сервер МАЯК недоступен.

- В клиент встроено ядро Xray-core v1.260327.0 (MPL-2.0): VLESS
  (tcp/ws/grpc/xhttp/httpupgrade, tls/reality, vision), VMess, Trojan,
  Shadowsocks (AEAD и 2022), Hysteria2 (salamander).
- Форматы подписок: список ссылок, base64, Clash/Mihomo YAML.
- Режимы `-subs`: `off`, `reserve` (по умолчанию — свой сервер основной,
  при двух провалах проверки переход на подписки и обратно при восстановлении),
  `always`.
- Встроенные пресеты публичных подписок; проверка с ограничением нагрузки
  (до 150 кандидатов, TCP параллельно, затем реальный запрос у лучших,
  отдельно проверяется, открывает ли выход заблокированные сайты).
- Повторная проверка живых узлов каждые 30 минут, полный прогон каждые 6 часов.
- Необязательная команда `mayak picker` — серверный отбор подписки.
- Android 0.3.0 (`versionCode` 4): карточка запасного входа, переключатель
  режима подписок. APK только arm64 (~11 МБ; клиент вырос из-за Xray).
- В VPN-режиме по-прежнему нет UDP (звонки мессенджеров через VPN не идут).

## 0.2.1 — 2026-11-17

Правки панели и настройки обхода DPI в приложении.

- Приёмы `-desync` (через запятую, порядок = порядок попыток):
  `tlsrec[:at=mid|sni|sniext]`, `multirec`, `split[:at=sni|mid|end|sniext|N]`,
  `disorder`, `fake[:ttl=N/md5]`, `oob`, `hmod`, `none`.
- `-debug` и журнал маршрутизатора; на лету: `POST /api/debug?on=1|0`.
- Android: подробный журнал (секреты скрываются), выбор приложений «мимо VPN»,
  приёмы DPI галочками, кнопки «Панель» / «Назад в приложение».
- Панель: подписи «Скачивание/Загрузка», переключатель режимов, таблица
  диагностики на узком экране.

## 0.2.0 — 2026-11-17

Прямой путь мимо DPI и встроенный VPN-режим на Android.

- Маршруты `-route tunnel|direct|auto`: прямой путь с обманом DPI на первом
  пакете, запоминание решения, переход в туннель при заморозке или ошибке
  ServerHello.
- Приёмы `tlsrec`, `split`, `disorder`, `fake`, `oob` (на Windows — tlsrec и split).
- DNS прямого пути через DoH (`-doh`).
- Android VpnService + hev-socks5-tunnel: режим «весь телефон», v2rayNG не нужен;
  приложение исключается из VPN. Режим «только прокси :1080» сохранён.
- Тесты в сетевых пространствах имён: `tests/desync-netns.sh`, `tests/vpn-netns.sh`.

## 0.1.0 — 2026-11-17

Первый выпуск мозаичного туннеля.

- Сервер и клиент: TLS 1.3, отпечаток Chrome 156 (uTLS), HMAC-авторизация,
  сайт-заглушка без ключа, нарезка потока на «плитки» против заморозки ТСПУ.
- Режимы `auto` / `mosaic` / `fast`, веб-панель, встроенная диагностика.
- Клиент для Windows, Linux, OpenWrt (ipk) и Android (прокси :1080).
- Сквозные тесты через симулятор ТСПУ (`tspusim`, `tests/e2e.sh`).
