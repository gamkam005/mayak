# МАЯК на MikroTik (RouterOS 7, контейнер) — пошагово для RB4011

МАЯК работает прямо на роутере в контейнере RouterOS: без OpenWrt, без отдельного
компьютера. Роутер отдаёт в туннель либо выбранные сайты (YouTube, Instagram, …),
либо весь веб-трафик сети. Остальное идёт как раньше, напрямую.

```
ПК/телефон ── LAN ── RB4011 ──(dst-nat 80/443 → 172.17.0.2:8443)── контейнер МАЯК ══ туннель ══ сервер МАЯК
                       └─ прочий трафик ────────────────────────────────────── напрямую к провайдеру
```

Как это устроено: роутер перенаправляет (dst-nat) нужные TCP-соединения на 80/443
в контейнер. МАЯК берёт имя сайта из самого соединения (SNI в TLS или Host в HTTP)
и ведёт его через свой туннель. Шифрование браузера не трогается: сертификаты
сайтов остаются настоящими. Внутри контейнера ничего не нужно: ни iptables, ни TUN,
ни привилегий.

> **Перед началом.**
> * Включение контейнеров (шаг 3) требует **физического доступа** к роутеру:
>   подтверждение делается отключением питания. **Роутер перезагрузится, интернет
>   пропадёт на 1–3 минуты.** Обновление RouterOS и установка пакета тоже
>   перезагружают его.
> * Wi-Fi и настройки LAN/WAN не меняются. Всё, что добавляется, помечено
>   `comment=mayak` и снимается одной командой (раздел «Откат»).
> * Проверено на RouterOS **7.25.1** (CHR, x86_64). Синтаксис `/container mounts`
>   и `/container envs` в старых 7.x другой, поэтому сначала обновитесь.

## Что понадобится

| Файл | Где взять |
|---|---|
| `mayak-container-full-armv7.tar` — образ для RB4011 (32-битный ARM) | релиз МАЯК на GitHub или `mikrotik/build-images.sh` |
| `link.txt` — ваша ссылка `mayak://…` | от того, кто поднял сервер |
| `container-7.xx.x-arm.npk` — пакет контейнеров **той же версии**, что RouterOS | mikrotik.com → Software → «Extra packages» для ARM |
| `mayak-install.rsc`, `mayak-route-list.rsc`, `mayak-route-all.rsc`, `mayak-panel.rsc`, `mayak-remove.rsc` | эта папка |

Образ **full** умеет запасной вход через бесплатные подписки: если сервер МАЯК
заблокирован, трафик пойдёт через найденный рабочий сервер. Образ **lite**
(`mayak-container-lite-armv7.tar`, 10 МБ) работает только через свой сервер.
Другие модели: hAP ac², RB3011, RB1100AHx4 тоже 32-битный ARM (`armv7`);
RB5009, hAP ax², ax³ и CCR2004 — `arm64`; CHR — `amd64`.

**Место.** У RB4011 нет USB и microSD, но внутренней памяти (512 МБ NAND) хватает:
образ full весит около 31 МБ и столько же занимает после распаковки. Свободное
место видно в `/system resource print` (free-hdd-space), нужно не меньше 100 МБ.
ОЗУ: контейнер занимает 35–60 МБ из 1 ГБ.

## 1. Резервная копия

Терминал WinBox (New Terminal) или SSH:

```
/system backup save name=before-mayak dont-encrypt=yes
/export file=before-mayak
```

Скачайте `before-mayak.backup` и `before-mayak.rsc` из Files к себе на компьютер.

## 2. Обновление RouterOS и пакет container

```
/system package update set channel=stable
/system package update check-for-updates
/system package update install
```

Роутер перезагрузится. Затем узнайте версию (`/system resource print`, строка
version), скачайте с mikrotik.com архив Extra packages для **ARM** этой версии,
возьмите из него `container-<версия>-arm.npk` и перетащите в WinBox → Files.
Потом:

```
/system reboot
```

После загрузки `/system package print` должен показать `container`.

## 3. Разрешить контейнеры (device-mode)

```
/system device-mode update container=yes
```

Терминал напишет, что ждёт подтверждения (до 5 минут). **Выдерните питание
RB4011, подождите 5 секунд и включите обратно.** Кнопку Reset **не зажимайте**:
если держать её при включении, сбросятся настройки. После загрузки проверьте:

```
/system device-mode print
```

Должно быть `container: yes`. Если там `no`, подтверждение не успели сделать
за 5 минут: повторите шаг.

## 4. Файлы на роутер

1. WinBox → Files: загрузите `mayak-container-full-armv7.tar` и четыре `.rsc`.
2. Там же создайте папку `mayak` (или `/file add name=mayak type=directory`)
   и положите в неё `link.txt`. Получится путь `mayak/link.txt`.

То же через scp с компьютера (адрес роутера свой):

```
scp mayak-container-full-armv7.tar mayak-*.rsc admin@192.168.88.1:/
scp link.txt admin@192.168.88.1:/mayak/link.txt
```

Ссылка лежит в файле и монтируется в контейнер как `/etc/mayak/link.txt`, поэтому
в конфигурацию роутера (export, бэкап) она не попадает.

## 5. Установка контейнера

```
/import file-name=mayak-install.rsc
```

> Запускайте `/import` **без** `verbose=yes`: в этом режиме RouterOS выполняет
> строки по отдельности и теряет переменные скрипта.

Скрипт создаёт `veth-mayak` (172.17.0.2), мост `containers` (172.17.0.1), NAT для
контейнера и правило, по которому контейнер обращается к DNS роутера. Затем
импортирует образ и запускает его (1–2 минуты). Если файлы или режим другие,
поменяйте в начале `mayak-install.rsc` строки `:local image`, `:local subs`
(`off | reserve | always`) и `:local route` (`tunnel | auto`).

Проверка:

```
/container print
/log print where topics~"container"
```

В журнале должно быть `МАЯК 0.3.5: прокси SOCKS5/HTTP на [::]:1080 …` и
`перенаправление: приём dst-nat на [::]:8443`.

Уже сейчас из LAN работают:
* прокси SOCKS5/HTTP `172.17.0.2:1080`. Можно прописать в браузере или в Telegram;
  Telegram ходит по IP без SNI, так что ему нужен именно прокси;
* панель `http://172.17.0.2:9090/` (с паролем, см. ниже): состояние, скорость, подписки.

### Веб-панель (с 0.3.4)

В панели четыре вкладки:

* **Узлы**: все серверы подписок, в том числе нерабочие, с текстом ошибки;
  TCP и реальная задержка в мс, ограниченные («только белые списки»), активный,
  выбранный, закреплённый. Кнопки «Выбрать», ★ (закрепить), ⚡ (замер скорости),
  «Проверить сейчас», «Скачать подписки и проверить», «Вернуть автовыбор».
* **Подписки**: свои адреса подписок и ссылки на серверы, встроенные бесплатные
  подписки, режим. Ключ в адресе показан как `***`; сохранение сразу применяется.
* **Настройки**: как часто перекачивать подписки и перепроверять живые серверы,
  адрес проверки задержки, «слушать подписку» (заголовок `profile-update-interval`).
* **Лог**: последние 500 строк, секреты скрыты.

**Пароль.** Панель слушает `0.0.0.0:9090`, поэтому без пароля она не открывается.
При первом запуске МАЯК сам создаёт случайный пароль в **Files → `mayak-data/ui.pass`**
(в журнал пишется только путь к файлу). Чтобы задать свой, положите одну строку
в `mayak/ui.pass` и перезапустите контейнер. Можно и через переменную:
`/container envs add list=mayak key=MAYAK_UI_PASS value=…`.
После 5 неверных паролей вход с этого адреса блокируется на минуту, при повторах
на дольше (до 15 минут). `MAYAK_UI_TLS=1` включает HTTPS с самоподписанным
сертификатом (отпечаток пишется в журнал).

**Доступ по адресу роутера.** Если роутер не главный шлюз сети (например, CHR в
виртуальной машине), до 172.17.0.2 из LAN не достучаться. Тогда:

```
/import file-name=mayak-panel.rsc
```

Скрипт делает dst-nat `<адрес роутера>:9090 → 172.17.0.2:9090` только с
интерфейсов LAN и разрешает это в forward, остальной доступ к 9090 закрывает.
В начале скрипта можно задать один интерфейс и сеть, например
`:local inif "ether1"` и `:local lannet "192.168.88.0/24"`.
Панель: `http://<адрес роутера>:9090/`. Если правите `.rsc` в Windows, сохраняйте его
в UTF-8 **без BOM**, иначе `/import` ответит `expected command name (line 1 column 1)`.

### Периоды и смена серверов

* Подписки перекачиваются раз в 6 ч, живые серверы перепроверяются раз в 30 мин.
  Оба периода меняются в панели (Настройки) или в `mayak/subs.json`:
  `"refresh": "6h"`, `"recheck": "30m"`, `"test_url": "…"`.
* Если подписка присылает `profile-update-interval: 1` (раз в час), МАЯК качает её
  раз в час, но не чаще раза в 15 минут. Отключается галочкой «слушать подписку»
  или `"honor_update_interval": false`.
* Если на активном сервере случился сбой, МАЯК сразу, вне очереди, проверяет его
  ещё 2 раза настоящим запросом. Если ни одна проверка не прошла, сервер считается
  нерабочим и трафик уходит на следующий живой. Если хотя бы одна прошла, сервер
  остаётся.
* Если после обновления подписки у активного сервера поменялись настройки (SNI,
  ключ, порт), МАЯК сразу переходит на новые. Если сервер пропал из подписки,
  МАЯК переходит на следующий живой.
* Если выбранный вручную сервер перестал работать, МАЯК возвращается к
  автовыбору, пишет об этом в журнал и показывает в панели.

## 6. Что пускать через туннель

### Вариант А — только выбранные сайты (рекомендуется)

```
/import file-name=mayak-route-list.rsc
```

Для каждого сайта из списка в скрипте создаётся запись `/ip dns static … type=FWD
match-subdomain=yes address-list=via-mayak`. Когда устройство в сети спрашивает
у роутера адрес, например, `www.youtube.com`, роутер узнаёт его через свой DoH
(1.1.1.1/8.8.8.8, провайдер ответ не подменит) и кладёт IP в список `via-mayak`.
Соединения TCP 80/443 к этим адресам уходят в контейнер. QUIC (UDP 443) к ним
запрещён, поэтому браузер сразу переходит на TCP.

Добавить сайт:

```
/ip dns static add name=example.com match-subdomain=yes type=FWD forward-to=mayak-doh address-list=via-mayak comment=mayak
```

Важно:
* устройства должны брать DNS у роутера (так выдаёт DHCP по умолчанию).
  «Безопасный DNS» в браузере и «Частный DNS» на Android ходят мимо роутера, и
  список не заполняется. Отключите их или используйте вариант Б;
* после добавления сайта откройте его заново (или перезапустите браузер): уже
  открытые соединения продолжат идти напрямую.

### Вариант Б — весь веб-трафик

Откройте `mayak-route-all.rsc` и впишите в `:local server` IP своего сервера МАЯК
(адрес после `@` в ссылке; без него запасные подписки тоже работают, но с ним
надёжнее). Затем:

```
/import file-name=mayak-route-all.rsc
```

Через туннель пойдут все TCP 80/443 из LAN, кроме локальных сетей. UDP 443
запрещается, остальной UDP (игры, звонки) идёт напрямую. Переключиться обратно
на вариант А: `/import file-name=mayak-remove.rsc`, затем шаги 5 и 6А.

### Проверка

С компьютера в LAN откройте https://api.ipify.org: он есть в списке варианта А,
и должен показаться IP сервера МАЯК (или запасного сервера). https://icanhazip.com
в списке нет: там будет ваш обычный IP. В варианте Б оба покажут IP сервера.

## 7. Откат

Снять перенаправление и удалить контейнер (роутер вернётся к прежней работе,
перезагрузка не нужна):

```
/import file-name=mayak-remove.rsc
```

Файлы в Files (образ, `mayak/`) удалите вручную, если они больше не нужны.
Полный откат дополнительно:

```
/system package uninstall container
/system reboot
/system device-mode update container=no
```

(выключение device-mode тоже может попросить подтверждение питанием). Крайний
случай: `/system backup load name=before-mayak.backup`.

## Ограничения

* Через туннель идут только TCP-соединения на 80/443 с именем сайта (SNI/Host).
  Соединения по голому IP без SNI в режиме перенаправления сбрасываются. Таким
  приложениям (Telegram) нужен прокси `172.17.0.2:1080`.
* IPv6 не перенаправляется (контейнер на IPv4). Если провайдер даёт IPv6, сайты из
  списка могут уйти по нему напрямую. Отключите IPv6 для LAN
  (`/ipv6 settings set disable-ipv6=yes`) или не раздавайте его клиентам.
* В режиме `subs=reserve` МАЯК, перейдя на запасной сервер, возвращается на свой
  после перезапуска контейнера (`/container stop`, `/container start`).
* Скорость на RB4011 не измерялась. У этого процессора нет аппаратного AES для
  программ, так что ожидайте десятки Мбит/с, а не гигабит.
* Сборка образа воспроизводимая: `mikrotik/build-images.sh` из исходников даёт
  те же байты, сумма есть в `SHA256SUMS` релиза.

## Как проверяли (RouterOS 7.25.1 CHR, виртуальная машина)

* Пакет container 7.25.1 встал. `device-mode container=yes` подтвердился
  «выключением питания» ВМ.
* Образ `mayak-container-*-amd64.tar` импортирован, запущен с `start-on-boot`.
  Контейнер full занимает около 36 МБ ОЗУ.
* Прокси 172.17.0.2:1080: внешний IP через контейнер совпал с IP сервера МАЯК.
* Устройство в LAN (тестовый контейнер за роутером), вариант А: `api.ipify.org`
  показал IP сервера МАЯК, `icanhazip.com` — обычный IP, `www.youtube.com` сам
  попал в `via-mayak` через DNS. В варианте Б оба сайта показали IP сервера.
* Сервер МАЯК закрыт фильтром (имитация блокировки), образ full с `subs=reserve`:
  через ~40 с МАЯК проверил 150 серверов из подписок и пустил трафик через
  рабочий (США, shadowsocks). Внешний IP сменился на IP этого сервера.
* `mayak-remove.rsc` снял всё: трафик снова пошёл напрямую, в конфигурации не
  осталось ни одного объекта с `comment=mayak`. Повторный запуск скриптов
  ошибок не даёт.
* Бинарники armv7 и arm64 из образов проверены под эмуляцией (qemu-user):
  прокси и приём по SNI работают. На живом RB4011 образ armv7 пока не запускали.
* Бесплатная лицензия CHR ограничивает скорость 1 Мбит/с, так что замер скорости
  в ВМ (~0,5 Мбит/с) о МАЯК ничего не говорит.

## Своя сборка образа

```
OUT=./out mikrotik/build-images.sh      # шесть образов: {lite,full}×{amd64,arm64,armv7}
docker load -i out/mayak-container-full-amd64.tar     # тот же tar подходит docker/podman
docker run -d -p 1080:1080 -p 9090:9090 -v $PWD/link.txt:/etc/mayak/link.txt:ro mayak:0.3.5-full
```

Настройки контейнера задаются переменными окружения `MAYAK_<ФЛАГ>` (любой флаг
`mayak client`: `MAYAK_LINK`, `MAYAK_SUBS`, `MAYAK_ROUTE`, `MAYAK_REDIRECT`, …).
Флаги командной строки важнее переменных. В образе по умолчанию:
`MAYAK_LISTEN=0.0.0.0:1080`, `MAYAK_UI=0.0.0.0:9090`, `MAYAK_REDIRECT=0.0.0.0:8443`,
`MAYAK_NOUPDATE=true` (образ обновляется заменой tar, а не сам),
`MAYAK_SUB_STATE=/data/subs`.

С 0.3.5 полезны для опытов: `MAYAK_BUDGET=8000` (плитка mosaic своего сервера,
по умолчанию 14000; то же поле есть в настройках панели) и
`MAYAK_SUB_FREEZE_URL=-` (выключить тест загрузки 256 КБ через узлы подписок).
